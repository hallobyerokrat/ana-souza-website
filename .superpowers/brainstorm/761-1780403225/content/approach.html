A — Eigene Admin-Seite

Wir bauen /admin direkt in die Website. Ana loggt sich mit E-Mail + Passwort ein. Fotos gehen zu Cloudinary (kostenlos), Texte in Supabase (schon vorhanden).

Vorteile

  • Alles auf einer Domain
  • Kein extra Account nötig
  • Volle Kontrolle über das UI

Nachteile

  • Mehr Bauaufwand (~4–6h)
  • Wir bauen das UI selbst

B — Keystatic CMS

Fertiges CMS-Tool das wir einbinden. Ana bekommt ein sauberes Editor-Interface unter /keystatic. Inhalte werden als Dateien im Repo gespeichert. Keine externe Datenbank nötig.

Vorteile

  • Professionelles UI sofort fertig
  • Schnellere Umsetzung (~2h)
  • Kostenlos (bis 3 User)

Nachteile

  • Separates Tool (neuer Login)
  • Videos: Dateigröße-Limit im Repo

C — TinaCMS (Visuell)

Ana sieht ihre echte Website und klickt direkt auf Texte/Bilder um sie zu bearbeiten. Kein separates Admin-Interface. Intuitivste UX — aber mehr Entwicklungsaufwand.

Vorteile

  • Einfachste UX für Ana
  • "Was du siehst, bearbeitest du"

Nachteile

  • Höchster Aufwand (~8–10h)
  • Komplexe Integration in bestehende Seite

Meine Empfehlung: A (eigene Admin-Seite) — passt zur bestehenden Supabase-Infrastruktur, Ana bleibt auf ihrer Domain, und wir haben volle Kontrolle.
